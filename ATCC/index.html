Air Traffic Control Center

Most air traffic games put you in a tower, turning aeroplanes onto a runway before they run out of fuel. ATCC does something far stranger and far more interesting: it sits you at an en-route radar console in the middle of American airspace and expects you to do the actual job. It is not a game that has been researched. It is a simulator that happens to be free.

Not the tower game you remember

En-route control is the part of the system nobody makes games about. You are not sequencing arrivals onto a strip of tarmac; you are holding a volume of sky perhaps two hundred miles across, moving traffic between the centres either side of you, and keeping every pair of aircraft apart by the margins the rules demand. Aircraft arrive on your scope already airborne and leave it still airborne. Success is uneventful.

That makes the first ten minutes genuinely hostile. There is no tutorial level. You get a scope, a keyboard, and a manual that tells you — correctly — that there is no way around reading it.

The data underneath is real

What lifts ATCC out of the hobbyist pile is that the airspace is not invented. Open the installed folder and the files are sorted by Air Route Traffic Control Center, using the FAA's own identifiers:

CentreSectors modelled
ZLA — Los Angeles19, 38
ZNY — New York66, 97
ZAU — Chicago75, 82

Each centre brings its own set: airways, fixes, airports, airline callsigns, radio frequencies, preferred routes, and a separation table. Six sectors does not sound generous until you realise each is a real piece of sky with real geometry, and that the sector documentation runs to a map and an information sheet apiece. The aircraft performance data is split between airline types and general aviation, so a light twin does not climb like a 757.

The practical consequence is that what you learn transfers. Clearances you issue here use the phraseology and the logic a controller actually uses, which is a rare thing to be able to say about something distributed for nothing.

There is a plain reason for that. Xavius's own company page says ATCC was “developed by an experienced controller”, and it shows in places a researcher would never think to look. The monthly newsletters that ran alongside the sim were written by working controllers and read like shop talk rather than marketing — one contributor recounts their own deal at real-life L.A. sector 4, later downgraded to a non-event, as an illustration of how a fourteen-year routine comes apart. This is people describing the day job.

What comes with it

The package is unusually complete for freeware of this vintage. Alongside the simulator you get a full manual, a command reference card, an airline reference card, and for each of the six sectors both an information sheet and a map. The manual doubles as a primer on the wider business of aviation, which is why it is worth reading even if you never fly a single session.

Version 1.0 is the free one and it is fully functional. Its only omission is sound: pilots answer you in text rather than speech. Version 1.1 added talking pilots and was the paid upgrade, and it is also the version that has aged worst — it was a 16-bit application, which modern Windows will not run at all.

That paid version was quietly set free in the end, and the Wayback Machine catches the moment. In 2007 the download page still told you to buy a registration code to unlock it. By 2009 the same page simply printed one — A318X2229433 — for anyone who wanted it, and it was still there in 2016. Somewhere between those two captures a product that had been sold became a product given away, and nobody announced it.

Free to use is not the same as free to pass on: the 1.1 licence carries no redistribution clause, and none of the installation-package exception that 1.0 has. The published code unlocked the copy you downloaded from Xavius — it did not make the installer yours to hand on.

Why the talking version needs Windows

Those two facts about 1.1 — that it gained speech, and that it needs an old Windows — are the same fact. Open the package up and the simulator is still a DOS program, launched through a PIF, drawing with the same Borland stroked fonts 1.0 uses. What is new is 807 numbered sound files and a small Windows program sitting alongside, whose job is to play them.

So the pilots' voices are not part of the simulator. They are a Windows companion feeding clips to a DOS program that has no way to make a sound itself. Run the DOS half on its own and it behaves exactly like 1.0: the same sim, the same sectors, and silence where the readbacks should be.

That is why 1.1 wants a period-correct machine rather than a DOS box. It is also why it has aged worse than the version that came before it — the part that made it worth paying for is the part tied to an operating system nobody runs any more.

Hollywood borrowed the scopes

The sim was convincing enough that television came looking for it. In Blackout Effect, broadcast by NBC on 4 January 1998, the radar displays are — in Xavius's own words from their newsletter at the time — “a special ‘Hollywood’ version of ATCC, with puffy datablocks and little blue triangles instead of green backslashes”. The story turns on a mid-air collision in sector 82, which is one of the six the sim ships.

The consoles then had a second career. When A Wing and a Prayer followed on the USA Network on 22 April 1998, the newsletter notes the props had been borrowed, or stolen, from the Blackout Effect set — and that keen viewers would spot ATCC sectors 66 and 97 filling the background radar screens, though not the closeups.

The Kiefer Sutherland picture Ground Control (1998) is described there as Xavius-assisted too, and its controller works sector 75. It is the one of the three you can still watch easily, though it took its time arriving: released in Italy that August, it did not reach American screens until March 1999. Henry Winkler is in it as airport engineer John Quinn, fighting to keep the facility's equipment alive while the weather takes the tower's power with it — and by one review's reckoning the only name besides Sutherland's to make much impact. Whether its consoles came off the set of Apollo 13 was, the newsletter says, neither confirmed nor denied.

Running it today

ATCC is a DOS program wearing a Windows installer, and that shows its age in one specific way: left alone, it tends to freeze after ten or twenty minutes. The package ships a small batch file that adjusts the DOS startup settings to suit it, which is the fix, and a second one to put the settings back. Under anything modern you are going into a DOS environment to run it, and the official advice is blunt about that being awkward.

The configuration we ran it on was Windows 98 in a PCem virtual machine — a period-correct host, which sidesteps the question of what today's Windows will and will not do with a DOS program of this vintage. If you are going to the trouble of a virtual machine anyway, that is the version of the problem worth solving.

We have not bundled it into GenX-DOS. This is a page about a piece of software, not a machine we emulate — and the simulator is still available from the people who made it, which is where it should come from.

The original downloads, including ATCC, the newsletter archives and the sector documentation, remain online at xavius.com/downloads.html.

Setting up the talking version

Because the voices need Windows, 1.1 wants a machine of its own era. This is what worked here rather than a guaranteed recipe — period hardware emulation is fussy, and the right answer varies with the machine you emulate.

Four things are needed, and two of them are yours to provide:

  1. A PC emulator. We used PCem; 86Box is the same idea and more actively maintained. Both emulate period hardware properly rather than approximating it, which is the point — this is software that cares what sound card it is talking to.
  2. A machine BIOS for whichever PC you emulate. Not supplied with the emulators, and not something we can help with: it is copyrighted firmware and yours to source.
  3. Windows 98, with a licence for it. Also yours. 95 should serve as well; the requirement is an operating system that still runs a DOS program under a Windows desktop, which is exactly what the generation after it stopped doing.
  4. ATCC 1.1 itself. No longer on the current Xavius site, but preserved in the Internet Archive's capture of its download page, along with the registration code it needs.

Install Windows in the emulator first and get sound working there before ATCC goes anywhere near it — a silent install of the talking version is indistinguishable from 1.0, and you will not know which half is at fault. Then run the installer inside the guest and give it A318X2229433 when it asks for a registration code.

One trap is documented by Xavius themselves. The simulator tends to freeze after ten or twenty minutes, and the fix shipped in the package is a batch file that clears the DOS startup files to free conventional memory. It copies config.sys and autoexec.bat to .old and deletes the originals; a second batch file copies them back. Reversible, then, but it is deleting the guest's boot files to do it, so take a snapshot of the virtual disk first — and note that running the fix twice would overwrite the backups with the empty state.

If you only want the simulation and can live without the readbacks, none of this applies: version 1.0 is the same sim, it is the one with permission to be passed around, and it asks far less of you.

Who made it
