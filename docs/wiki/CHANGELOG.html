[Unreleased]

Changed

  • jimbro1000 is credited in ATTRIBUTION for the CoCo artifact-colour suggestion, alongside dplassgit's Model 100 proposal. The docs caught up with the CoCo work at the same time: the README's gamepad section covers the CoCo's native joystick path and why a pad there needs Firefox, and the XRoar wiki page gained the artifact-colour table, the joystick traps and the browser limitation. The wiki's file index had fallen behind by two shared scripts.

Added

  • The CoCo pages now say when the browser cannot see a gamepad. An orange strip in the same style as the audio banner: "This browser cannot detect a USB gamepad -- use Firefox to play with one." Chromium browsers never hand a pad to these pages — the emulator asks the browser what joysticks exist once, at startup, and Chrome will not answer for a page that does not have focus, so by the time a pad could be admitted nothing is still asking. Firefox has no such rule and the same pad works there at once. This is not particular to us: XRoar's own online build lists the pad in Firefox and not in Chrome with the same pad plugged in. Since it cannot be fixed from the page, it is at least worth saying plainly. Dismissible, and it stays dismissed.

Fixed

  • A gamepad may need a second press in Chrome. Chrome only reveals a gamepad to a page that currently has focus; Firefox does not require it. A pad pressed while the window is not focused is invisible to the page, and there is nothing the page can do about it — so the controls page now says to click the game area first and press again. The same rule is why the CoCo pad appeared to work in one browser and not the other with identical code.
  • Polaris was documented as an entirely different game. Its page described a side-view submarine arcade port — piloting a sub, dodging depth charges from destroyers and helicopters, credited to Sega in 1983. None of that is this game. Tandy's Polaris is by Device Oriented Games, 1981, and it is a Missile Command: six islands, three dug-in submarines with nine missiles apiece, and a pair of crosshairs you steer onto missiles raining from the sky. The page has been rewritten from the cartridge manual — controls, scoring, the point multiplier, the bonus island at 2,000 points and the explosions that wrap round the screen edges. The confusion is at least an understandable one: Polaris was the submarine-launched ballistic missile, the game really does fire from submarines, and Sega shipped a 1980 arcade game of the same name that is the side-view submarine game described.
  • Polaris now gets the right joystick port. The manual is explicit — "the right joystick is for one player, the second player will use the left joystick" — and it had been wired to the left, which is why a gamepad did nothing at all. Aiming is on the joystick; firing stays on the keyboard, where the game put it: Z, X and C launch from the three submarines.

Added

  • The CoCo now shows composite artifact colour, where the game was drawn for it. The Dragon/CoCo's high-resolution modes were nominally two-colour, but on an NTSC television alternating pixel columns come out red and blue — and games were drawn for that. Demon Attack is meant to be black, white, red and blue; it was rendering in stark monochrome. XRoar models this with -tv-input, and the bundle now passes it per game ("tv": "cmp-rb" in games.json), because it only means anything for titles that relied on it and the artifact phase differs between them. Enabled for Demon Attack, Downland, Canyon Climber and Mega-Bug — four of the ten, each checked on screen. Suggested by jimbro1000, who also identified the option. Testing it globally showed why it belongs per game — and that the split is not the one you would guess. Canyon Climber and Mega-Bug turned out to need it badly (without it Canyon Climber is an unreadable black-and-white dither, and Mega-Bug's insects are white blobs), while three titles are actively harmed: Dungeons of Daggorath, Monster Maze and Poltergeist are meant to be clean white on black, and composite decoding fringes their line art blue and orange. The rest are unaffected either way — Popcorn and Polaris use colour and text modes that do not artifact at all, and Galactic Attack's green mode is untouched by it.

Added

  • USB gamepads work on the CoCo. Plug one in, press a button, and it takes over the joystick — left stick to move, A to fire — the CoCo's joystick had one button, so that is the one that matters (B reaches a second button a few games read; X and Y do nothing). Browsers deliberately hide gamepads until a button is pressed, so that first press is unavoidable and the page now says when the pad has connected. This needed more than an option. XRoar enumerates joysticks once at startup, and since the browser has revealed nothing by then its log reads "no devices found" even with a pad plugged in; nothing re-scans afterwards. It also reports what joysticks exist through UI callbacks this page had stubbed out as empty functions, so a connected pad was invisible to us by construction. The page now implements those callbacks, listens for the browser's connect event, and binds whatever XRoar reports — by its own name rather than a guessed one.
  • Joystick support on the CoCo. Several titles are joystick-only — Galactic Attack says "PRESS FIRE BUTTON TO BEGIN" and ignores the keyboard entirely — so until now they could not be started at all. The bundle passes XRoar's own -joy-left / -joy-right per game, which is the emulator's real joystick rather than faked key presses: a physical pad is picked up natively through SDL, and XRoar's keyboard joystick (cursor keys to steer, Alt to fire) covers players without one. On for Galactic Attack, which cannot be started any other way. Not for Polaris or Poltergeist: both were given one on the assumption they needed it, and testing each in play showed otherwise — Polaris ignores a joystick on either port, and Poltergeist is steered with the cursor keys, which a keyboard joystick takes away from the game. A joystick is only wired up where the game actually wants one. The port matters and is not the obvious one: -joy-right left Galactic Attack sitting on its title screen, -joy-left started it at once.

Fixed

  • The CoCo browser tab said "XRoar". The tab is supposed to name the machine, never the emulator, and the page's own <title> was correct — but XRoar's SDL layer overwrites the window title once it starts, after the page has set it. It is now put back whenever that happens.

Changed

  • Soft keys now appear only on the games that use them. A CLEAR button on a game that never asks for CLEAR is noise, and worse, it implies the game wants it — a player pressing it learns only that it does nothing. The button now shows where the game's own page says the key is used: six of the ten TRS-80 games, and four of the twenty BBC games, so twenty buttons that meant nothing have gone. The map is generated from each gamedoc's Controls table by tools/build-softkey-map.py, so the button and the documentation cannot disagree — add a CLEAR row to a gamedoc and the button appears next build. It reads the Controls table only: the "Getting started" text used to hedge with "press the key it names to begin (often CLEAR)", which was true of nine TRS-80 pages and told a reader nothing. If the map can't be loaded the keys all show, because hiding the only discoverable way to start a game is far worse than one extra button.
  • The TRS-80 now renders at the machine's own resolution. It had been drawing at 1024×768 and scaling down into the bezel — and once the picture was inset, down by two thirds, which turns a twelve-pixel-tall character into mush whichever filtering you choose. It renders at 512×384 now, so the ratio sits near 1:1 where text is legible. The scaling mode is chosen from the ratio actually on screen rather than fixed in CSS: crisp nearest-neighbour when the picture is scaled up, smooth when it is scaled down, because the cutout can land either side of 512 depending on the window.
  • The TRS-80 picture is nudged down so what you see is centred. Centring the surface on the cutout is not the same as centring the picture: the games don't fill the surface evenly — Galaxy Invasion's dotted frame runs from y 8 to y 335 of 384, so eight pixels above it and forty-eight below — and a mathematically centred canvas puts the visible frame high in the tube. It is offset by half that difference, which brings the frame's margins to within a pixel of each other.
  • The TRS-80 picture is inset within the glass rather than running to its very edge. The black backdrop was enlarged to cover the whole cutout at the same time, so the rest of the tube reads as an unlit CRT face instead of as a hole with wallpaper behind it.

Fixed

  • Six TRS-80 gamedocs didn't mention the key that starts the game. Making the gamedocs decide which buttons appear meant checking they were right, and they weren't: only Defense Command named CLEAR in its controls, though Galaxy Invasion, Cosmic Fighter and Attack Force all need it to start — Cosmic Fighter's own title screen says so in as many words. Crazy Painter uses it in play, and Space Castle takes CLEAR with BREAK to restart. Each game's text was read out of its own binary rather than inferred.
  • The TRS-80 controls page said CLEAR was "hyperspace in a few" games. It isn't. Super Nova's hyperspace is the spacebar; no game in the lineup uses CLEAR for it. The page now names which games use CLEAR and what for.

Changed

  • The BBC COPY button has joined the rest of the soft keys under the machine. It was the last one still alone in the top-left, so the family disagreed with itself — TRS-80 CLEAR and the Atari console keys had already moved. Same amber style, same place. Being at the bottom it also clears the suspended-audio banner, which is fixed to the top at a very high z-index and had been burying it at exactly the moment a player goes looking for a control.

Added

  • check-doc-counts.sh now checks wording, not just numbers. Counts have always drifted loudly and the script caught them; prose drifted silently — when the soft keys moved out of the top-left corner, several documents went on describing them there and nothing noticed. There is now a blocklist of phrases that were true once, each with the paths it may legitimately still appear in, since history is not drift and a comment explaining what a control used to do is not a stale claim. It found two pages on its first run — both BBC controls pages still told players the COPY button was top-left.

Fixed

  • The BBC COPY key was being delivered four times per click. The same bug already fixed in the Atari and TRS-80 scripts, and the last copy of it: the synthetic key was dispatched at document, window, body and the canvas, and those events bubble. One dispatch now, at document.

Fixed

  • The TRS-80 screen was dropping pixel rows, and taking the tops off letters with them. "High Score" read as "-igh Score" and "Space" as "Scace". The canvas renders at 1024×768 and the bezel cutout is smaller, so the browser is always scaling it down — and it was told to scale with nearest-neighbour, which does not average pixels, it discards them. On a TRS-80 character twelve pixels tall that is enough to remove the top of the glyph. It now downscales smoothly, so every row survives. A leftover transform: scale() from the Model I bezel went at the same time — it was shrinking the picture inside its own hole and making the scale factor worse. Nearest-neighbour is still right everywhere else: every other bundle renders smaller than its cutout and scales up, which is the case it is good at.

Changed

  • Eliminator is out; Space Castle is in. Eliminator had been shipping dead — a black screen, and not because of the Model III: it did the same on the Model I. The file was structurally perfect, which is what made it worth chasing. It turns out our copy is byte-identical to the upstream self-contained conversion, so that conversion is broken at source; and the genuine binary — identical on both the Model I and Model III public-domain discs — loads above where the DOS sits and wants the DOS resident, so on a bare machine it loads, runs, and fills the screen with garbage. There is no Model III build to find. In its place, Space Castle (Cornsoft Group, 1982, Charles Guy): rotate, thrust and shoot through three spinning armour shields to the Castle at the centre — a different shape of game to the side-scrolling shooters that make up most of the lineup, and it carries its own rules screen on ?. Ten games still, and the controls on its page are taken from that rules screen rather than inferred.

Changed

  • The TRS-80 bundle is now a Model III, not a Model I. The Model III runs the Model I library, so the ten games are unchanged — but it is a far better machine to put in front of a visitor: one case instead of a monitor, an expansion interface and a drive stack cabled together across the screen, a 2.03 MHz Z80 instead of 1.77, lower-case as standard, and a keyboard with a numeric keypad. New bezel to match. The switch cost two strings, because the ROM is now fetched and written into the emulator's filesystem at boot instead of being baked into the WASM — the old build fixed the machine at compile time, so changing it would have meant a full emscripten rebuild for a 14 KB file.
  • The TRS-80 CLEAR button looked disabled. Grey text on a grey border at 0.6 opacity, alone in the top-left corner — which is how a dead control looks, and CLEAR is the one button that starts most of these games. It is now in the amber style the rest of the site uses, sitting under the machine in front of the keyboard, alongside where the Atari console keys sit on their pages.

Fixed

  • The TRS-80 CLEAR key was being delivered four times per click. The same bug fixed in the Atari scripts, still present here: the synthetic key was dispatched at document, window, body and the canvas, and those events bubble. One dispatch now, at document.

Fixed

  • A hairline of wallpaper showed around the Atari 400 and 800XL screens. The cutout in the bezel has a soft, anti-aliased edge, and with nothing behind it the wallpaper showed through that fringe. Every other bezeled bundle already carried a black .screen-bg layer for exactly this — the 7800 uses one with the very same bezel — and these two were the only ones without it.

Changed

  • All the Atari soft keys now sit under the set. The 400 and 800XL keys were top-left while the 2600 panel and the 7800 keys sat between the TV's legs, so the family disagreed with itself. All four are centred beneath the screen now, where a console lived — and being at the bottom they clear the suspended-audio banner without needing the offset the top-left placement required.
  • 40 gamedocs now name the button, not just the key. Every instruction that said "Press F4 Start" or "Press Enter (Reset)" now reads "Click START (or press F4)" — the button first, since it is the thing on screen, with the key kept as the alternative. 81 replacements across the Atari 400, 800XL, 2600 and 7800, applied from an explicit phrase map rather than a loose pattern, ordered longest-first so overlapping phrasings could not double-apply. The bold names match the on-screen legends exactly.

Added

  • The Atari 2600 and 7800 switch panels are on screen. The whole panel, in the console's own left-to-right order and with its own lower-case legends stacked the way they were printed: tv type, left difficulty, right difficulty, game select and game reset on the 2600; and on the 7800 just PAUSE, SELECT and RESET as plain keys, matching the Atari 400/800 ones — its case carried no difficulty switches, whatever ids the core exposes for 2600 compatibility. Power is left off, since it means nothing here. The momentary switches are buttons and the two-position ones are switches that stay where you put them, and the panel sits under the set — between the TV's legs, where a console actually lived. Switches that sat on the console itself, physically labelled, and that games depend on — switches that sat on the console itself, physically labelled, and that games depend on: RESET is how most 2600 titles begin, and SELECT picks the variation, which on a 2600 cartridge is often the difference between one game and thirty. Same reasoning as the Atari 8-bit keys, and the same place on screen. These needed a different mechanism. Everywhere else a soft key dispatches a synthetic KeyboardEvent, because those engines read the DOM's keyboard events; EmulatorJS does not, and ignores them outright — firing V at the 2600 left the variation number exactly where it was. They go through gameManager.simulateInput() instead, the same path EmulatorJS's own on-screen controls use, with the button ids read from its source rather than guessed.
  • OPTION, SELECT and START are now buttons on the Atari 400 and 800XL. The Atari 8-bits put those three on their own labelled keys beside the keyboard, and most games will not begin until you press START — but in a browser there is nothing to see, so a game sits on a silent title screen and a player has no way to guess the way in is a function key. Reported by a reader as "it's not obvious how to hit custom keys, like the Atari 8-bit OPTION key". They were always on F2/F3/F4 and always documented; what was missing was the labels the machine used to have. RESET is deliberately not among them — it is one mis-click from throwing a game away. The buttons appear straight away but stay greyed for a few seconds while the machine boots, because a console key delivered mid-boot crashes the emulator outright, and clicking START repeatedly at a silent screen is exactly what an impatient player does.

Fixed

  • Soft-key buttons were hidden behind the audio banner. The "browser has suspended audio" banner is fixed to the top of the screen with a very high z-index, and the soft keys sit at top: 8px — so while audio was suspended, which is precisely when a player is hunting for a control, the button was buried underneath it. The TRS-80's CLEAR has been in that state since it shipped; the Apple ][+ Flip Disk button joined it. The banner now publishes its height as --gx-banner-h and the soft keys sit below it, dropping back flush when it clears.
  • Soft-key buttons were delivering each press four times over. The shared soft-key pattern dispatches its synthetic key at document, window, body and the canvas "to be safe" — but the events bubble, so one click arrived at window four times and the emulator saw the key pressed four times. A few clicks in quick succession flooded atari800 into memory access out of bounds and a black screen. Now one dispatch at document, measured at exactly one keydown per click, and fifteen rapid presses no longer disturb it.

Added

  • The Oregon Trail can now be finished. It shipped on a two-sided floppy and stops partway through to ask you to turn the disk over — and side B was never bundled, so the game ended there. Reported by a reader of the Tweakers write-up, who got exactly that far. Both sides now ship as .woz (apple2js reads the format natively, so nothing is converted), and a Flip Disk button sits at the top left of the Apple ][+ screen for this game, swapping the disk in the running drive the way turning it over did. No single-disk release exists to fall back on: every candidate turns out to be side A, and the catalogue gives it away — there is a file on it called FLIP.LIB. The button is deliberately not labelled "flip to side B": the game can ask for either side, more than once, and turning the disk over is one action either way.

Added

  • Contact address is now admin@genx-dos.fun rather than a personal Gmail, across removal requests, security reports and conduct reports. A project address that outlives any one mailbox, and it keeps a personal address off the repo and the site.
  • A removal request must now identify its sender and its basis. Previously it said a one-line message was enough, which would have let anyone strip the collection on an anonymous say-so. A request now needs three things: who is asking, their standing (rights holder, or who they represent and in what capacity), and the material plus the basis of the concern. Deliberately not raised further than that — no registration certificates, chain-of-title documents or legal citations, because the people most likely to ask are authors of forty-year-old games who never had paperwork. A request meeting those three points is taken in good faith and acted on immediately.
  • A plain removal-on-request statement — at the top of ATTRIBUTION, in the README, and linked from the foot of the home page, since the site is where a rights holder is most likely to arrive and the statement was otherwise three clicks deep. If a rights holder — or someone acting for one — raises a copyright or IP concern, the material goes immediately: no formal notice, no legal citation, no explanation required, and no argument. It covers everything here rather than only games: titles, system ROMs and BIOS images, emulator code, artwork, fonts, documentation, names and marks. The previous wording was scattered across four files, softer than intended, and read as though it applied to bundled titles alone; the issue template and CONTRIBUTING now say the same thing.
  • AI-DISCLAIMER.md — a short statement on the use of AI in building GenX-DOS: what it assisted with, and what it did not decide. Imported into the wiki like the other root documents, so it reads on the site as well as on GitHub. Linked from the foot of the home page, under the licence line — it belongs with the statements about the work rather than among the "Go further" cards, which are a fixed three.

Changed

  • Home page footer: the three lines now run shortest to longest, and CC BY-NC 4.0 links to the canonical licence text at creativecommons.org, carrying rel="license". The ordering gives the block a centred taper instead of a ragged middle.
  • The emulator-facing glue is now GPL-3.0-or-later; everything else stays CC BY-NC 4.0. systems/_shared/genx-*.js, systems/_shared-ejs/genx-*.js and the 29 play.html pages load and drive GPL emulator engines in the same browser context, which makes them part of a combined work with those engines — and the GPL does not allow further restrictions to be placed on such a work, which NonCommercial is. Each of those 44 files now carries an SPDX header, the GPL-3.0 text is in COPYING at the root, and LICENSE.TXT sets out the split and the reasoning. Nothing third-party is relicensed and the repository as a whole does not become GPL: the prompt, the writing, the artwork and the several hundred instruction pages remain NonCommercial.
  • ATTRIBUTION records where the source for each GPL binary lives. Distributing a compiled engine carries an obligation to make its source available, and mirroring someone else's build does not discharge it. There is now a corresponding-source table covering the EmulatorJS runtime, all 11 libretro cores, and the four engines built here.
  • o2em was recorded as GPL-2.0+ and is actually Artistic-2.0. Our bundled odyssey2/COPYING had said so all along and disagreed with the documentation; upstream settles it — libretro/libretro-o2em ships a COPYING that is the Artistic License 2.0, our copy is byte-identical to it, and no source file in the core carries a GPL header. The original O2EM was Artistic-licensed and the libretro port kept those terms. Corrected in ATTRIBUTION, the README engine list, and the Odyssey² controls page, which had been telling players the wrong licence.
  • ATTRIBUTION gained three credits that had been shipping unnamed, all found by walking the tree rather than the document: jQuery 1.11.0 in the TI-99/4A bundle (a separate copy from the Electron one already listed), Bootstrap Icons in the Apple ][+ bundle — its filenames are webpack content hashes, so it is only identifiable from the font's internal name table — and Font Awesome Free 6.5.1 inside the EmulatorJS runtime.
  • Every GPL binary now ships with its licence text. The GPL asks for the licence to travel with the binary, and most of the tree had none: 11 COPYING files now ship, up from 5. One copy in systems/_shared-ejs/ covers the EmulatorJS runtime and all 14 bundles that share it, because none of them carries its own core binary; the libretro cores get GPL-2.0 beside them; jsspeccy/, xroar/, jtyone/ and js99er/ get theirs. The permissive bundles (MIT / BSD) still need their upstream notice files, which carry per-project copyright lines that have to come from upstream rather than be written here.
  • Corrected a claim in ATTRIBUTION about upstream licence files. It said the LICENSE / COPYING file in each bundle covered that bundle's original. Only six carry one — the builds we compiled ourselves. The section now says which, and that for the rest the table and its upstream links are the record, so a missing file is not read as an unlicensed component.
  • deploy.sh now says why it cannot connect. When the deploy key is held in an ssh-agent and the agent has not been unlocked for the session, the connection fails with Permission denied (publickey) — which reads as a rejected key and sends you looking at the server. A preflight check now names the real cause and the one command that fixes it, and runs before the build rather than after it, so a locked key costs a moment instead of a full staging build.

It fetches before it compares anything: a clone that has sat untouched looks perfectly healthy until you do, so diffing against one reports pages as out of date when they are current. It rebuilds the in-repo HTML wiki first (the root CHANGELOG, README and ATTRIBUTION are imported as pages, so editing one leaves docs/wiki/ stale), leaves the wiki-only _Sidebar.md alone, and refuses to run when the clone holds unpushed commits rather than resetting over them. Appending rather than patching means the repo's own copy of the pill script can change without the overlay going stale.

[1.6.0] - 2026-08-16

Removed

  • The feature article's GX VERDICT panel. The mock magazine score-out-of-100 — authenticity, self-reliance, pedantry, lastability and a pull-quote — was a joke that had outlived itself: the article reads better ending on its own argument than on a rating of itself. The section and its CSS (.verdict, .meters, .overall) are gone.

Added

  • The screen now waits for its bezel. Every bundle draws a CRT or console bezel as a PNG and positions the canvas inside the screen hole in percentages of that image's box — so until the PNG arrived, the canvas and its black underlay were laid out against a box whose size wasn't settled, and appeared unframed, off-centre, or as a bare rectangle on the wallpaper. The Apple I and Atari 7800 were the most obvious, but every bundle did it to some degree. A new shared genx-bezel-ready.js, loaded synchronously in <head> on all 33 emulator pages, hides the whole screen stack — canvas, black underlay and bezel — until the bezel image has loaded and been through a layout pass, then reveals them together, so the machine arrives in one piece instead of assembling itself. It injects its own rule rather than relying on a stylesheet (six bundles don't load genx-frame.css), which also means a page can never be left hiding its canvas with no script to reveal it; a four-second failsafe covers a bezel that 404s or a bundle that turns out not to have one.
  • Save states can now be exported to a file and restored — so they survive a change of address. Browsers scope IndexedDB to the origin, and there is no cross-origin access, so save slots made at one address are simply invisible from another: not deleted, permanently unreachable. With the site gaining its own domain alongside GitHub Pages, that would have stranded every visitor's slots. A third backup drop-up now sits beside Save and Load on all 24 bundles that have them, offering export all saves — every slot on the whole site, not just the game on screen, written as one dated .json — and restore from file. Restoring is non-destructive: a slot that already holds a save is skipped rather than overwritten, so an old backup can never clobber newer progress, and the button reports what happened (restored 12, kept 3). New shared genx-savestate-transfer.js talks to the gx-savestate database directly rather than to any engine, so one file serves both the EmulatorJS bundles and the standalone ones; it also exposes window.GenXSaveTransfer for use without the button bar. The Your Data wiki page gained a section on backing up and on why moving address strands saves — it had told people to "export anything you want to keep first" since before there was any way to do so.
  • deploy.sh — one command to publish the site to genx-dos.fun. The site now has its own host (Namecheap shared, cPanel, LiteSpeed) alongside GitHub Pages, reached over rsync-on-SSH. The script takes a required target — staging or live — because the only thing separating a routine staging push from overwriting the public site is which word you type; live also asks for typed confirmation unless -y, and -n dry-runs. What ships is not decided here: it shells out to build-portable.sh and mirrors the result, so the shipping file set stays defined in exactly one place rather than drifting between two exclude lists. It builds fresh each run rather than mirroring _Portable/, so a stale portable folder can't become a stale website. Files on the server that aren't in the build are protected from --delete: .well-known (removing it can break certificate renewal), cPanel's cgi-bin, Namecheap's parking leftovers, and robots.txt — the repo has none, so without that filter the first staging deploy would strip staging's own noindex guard and make it crawlable. Afterwards it re-fetches five key paths plus the .wasm content type, because a deploy that reports success while the site 404s is the failure worth catching. Excluded from the portable build.
  • BBC Micro Thrust: USB gamepad flight. The launch line gains a GP.* remap so the pad flies it — d-pad rotates (Caps Lock / Ctrl) and up thrusts (Shift), A fires (Return, already the pad default) and B works the shield / tractor beam (Space).
