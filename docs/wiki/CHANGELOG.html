[Unreleased]

Added

  • COMMAND.COM is on the drive, and it credits LGR. The interpreter was the one file a DOS C: root always had and ours did not. It sits in the root now, and running it prints the start-up banner: GenX-DOS Version 1.8.1, then (☺)Copyleft Mike @ LGR - Lazy Game Reviews, then a blank line — where the "C" of "(C)" is the font sheet's smiley, character 1, the sheet being indexed by character code. The credit is the point of it: the terminal, the virtual filesystem and the font system are the LGR base written by Mike for Lazy Game Reviews, not our work, and the interpreter's own banner is where DOS always put that line. TYPE COMMAND.COM gives the same seeded garbage the launchers give, minus the MZ — a .COM has no header at all; DOS loaded one at offset 0x100 and jumped straight in, so the first byte on screen is already code. The copyright line is indented under the version line, the way MS-DOS set its own banner out. It answers from any directory because there is a PATH now: GENX_PATH holds the drive root, and attemptExec searches the current directory first and then each entry on it, which is the order DOS searched in. VER.COM sits beside it and prints the version line alone, then a blank line — in real DOS, VER was internal to COMMAND.COM rather than a file, but every other program on this drive is a file. Both carry a com key naming what they run, so adding a third is a line in the filesystem and a function beside the other two. The wiki's filesystem page carries the new com shape alongside link and data, since that page is what anyone editing fs.js reads. The version is a constant, GENX_VERSION, and two things keep it honest. check-doc-counts.sh compares it to the newest release heading here, and build-portable.sh refuses to build if they differ — which is the choke point for everything that leaves the repository: deploy.sh builds through it for staging and live, the portable copy comes from it, and so does the release zip. Nothing else in the tree derives that number, and it is exactly the kind of thing that sits a release behind unnoticed.

  • The legal position is a page now, and the pill points at it. The reasoning behind the licences, the ROMs, the artwork and the data was spread across five documents, none of which said how the parts fit together; the wiki's Legal position page does. The credit pill on every play page used to read removal and open the removal section inside the attribution file — it now reads legal and opens that page, because someone who has just found their own work here wants to know where we stand as well as how to ask, and the page opens with the position and links the procedure. It is also honest about the gaps, which is the point of publishing it: no robots policy, graphics attribution left to a single share-alike case, and no lawyer behind any of it.

  • REMOVAL.md — the removal procedure on its own page. It has always been in ATTRIBUTION.md, which is the right place for the record but a poor one to land on if you are a rights holder in a hurry. The standalone page says what is covered, the three things a request needs, where to send it, and what happens next — and adds what we can and cannot reach: the site and the repository including its history, but not other people's copies of the repository or third-party archives. It is in the wiki sidebar, and ATTRIBUTION.md points at it.

  • An ARCADE branch: ten makers, ten games each. C:\SYSTEMS\ARCADE\<MAKER>\GAMES, the same shape as CONSOLE\NES\GAMES, sitting at row 4 of the EMULATOR LAUNCHER with the wiki moved to 5. Makers are listed alphabetically, matching the CONSOLE menu — a menu ordered by a private ranking isn't self-evident to anyone but its author. Games run year ascending within each maker, and every launcher is named after its romset as the site's other launchers are. All 100 romsets are built and verified byte-exact against the core's own metadata — every member decompressed and its CRC recomputed, with no absent, wrong or extra file in any of them. They were built by CRC rather than by filename, because the core wants exactly what its own data file lists, and a current MAME set disagrees with it constantly on filenames and occasionally on which archive a chip lives in. Pairing the title list against the romset list by position would have filed four games under the wrong ROM — Battlezone as missile, Marble Madness as paperboy, Sheriff as spacefev, Bionic Commando as blktiger. Both lists were year-ascending but broke ties differently. Matched on each set's own recorded title instead. All 100 carry marquee artwork. The libretro set covers 97; the last three are Irem cabinets, and LaunchBox holds proper 3840px scans of the Image Fight and Ninja Spirit marquees that it does not. Traverse USA has no marquee of its own anywhere — every scan is the Williams "MotoRace USA" retitle, which is a wrong title rather than wrong branding, so re-badging it the way Moon Patrol was re-badged would not have been enough. Its marquee is instead built from the untitled artwork with the game's own title lockup lifted from its attract screen: snapped to the five colours the screen actually uses, the triangle refitted from its unobstructed right edge because the lettering fragments the rest, and cropped to the picture and its pinstripe frame — losing the red bands takes it from 3.0:1 to 4.0:1, which fills the cabinet’s marquee hole instead of letterboxing in it — and set in the starfield above the Gateway Arch — the artwork is St Louis, and the logo is sized to leave the arch clear — and toned down to the banner’s own levels. That last step is an exposure scale rather than a gamma curve: the screenshot’s colours run to 238-255 against printed card that peaks near 165, and no exponent moves a channel that is already at 255. The result matches what the machine puts on screen when it boots. Formerly, 97 of the 100 carried marquee artwork, normalised to the same 674x145 canvas as the originals. Gauntlet's is the one that needed cutting: the scan is a blank marquee, the version with an empty white instruction panel below the logo, so it is clipped to the wordmark. Every other candidate turned out to be legitimate artwork whose whiteness is clouds, star fields or a white ground — a whiteness test flags nine of them, and cropping on that basis removed Space Fever's title outright. What actually distinguishes a blank panel is a large featureless white block low down on a coloured ground with the art above it, and exactly one of the 91 matches that. The three without are all Irem — Traverse USA, Image Fight, Ninja Spirit — and a cabinet with no art shows an unlit marquee, which is a thing you actually saw in an arcade, rather than a broken-image icon, which is not.

  • The removal route leads with the email now. Every document listed the GitHub issue first and offered the address as the option for people who wanted it kept private, which reads as though an account is the normal way in — and a rights holder is often a brand or a representative who has no account and will not make one. REMOVAL.md, ATTRIBUTION.md, README.md, SECURITY.md and CONTRIBUTING.md now put admin@genx-dos.fun first and say no account is needed anywhere, with the issue kept for anyone who would rather it were public. The issue chooser carries the same route as its first entry, so it is visible before a form is started, and the removal template says an email saying the same things is equally good. That template also said the repository bundles the software, which the site does now, and promised removal immediately where the page says hours rather than minutes — both corrected.

  • The legal and policy documents describe the project as it is now. They had not been touched since 17/08, and the arcade section and the ROM-free repository both landed after that. Your Data lists the one file the arcade writes — a 20-byte input config that gives Hang-On's brake a pad axis, written into the emulator's save storage at boot — so the page is again the complete list it claims to be, and the clearing note names it. Removal upon request now covers the site as well as the repository, and says plainly that the games and the firmware we supplied are served by genx-dos.fun and are not in the repository at all. SECURITY points removal requests at that section, with the private email route, rather than at the issue tracker alone. CONTRIBUTING warns that a clone boots the machines but not the games until the files in ROMS.txt are in place. The licence names the game files and system ROMs as served by the site. The AI note said 33 systems, six days after it became 34 — check-doc-counts.sh now checks that line too. The arcade had slipped through attribution as well: the bundle, and the hundred romsets it serves — 1976-1989, ten manufacturers — had no row of their own, though the core did. Removal upon request now names sound among the things it covers, for completeness — the one sound the site plays, the coin effect, is licensed for this project and bought from its vendor, and the attribution says so.

  • Section headings are a smaller page title, not a stretched label. h2 had been uppercase Michroma at label size with wide tracking, which sets an uneven line — the face draws its caps to different heights, and the tracking pulls them apart. It is now the same face, case and tracking as the page title at 1.1rem, one step down in size, keeping the rule that runs off to the right. Every document on the site uses the one stylesheet, so the gamedocs, the controls pages and the wiki all follow.

  • Possessives that read as plurals. A sweep of the site text, the wiki source, the gamedocs and the code comments found 21 places where a possessive had its noun dropped and the bare 's was left to stand for it — "the last three are Irem's", "higher than the dealer's", "copy the two artifacts over the bundle's", and an arcade wiki heading that read "Romsets are the core's, not a modern set's". Each has its noun back. The apostrophes that remain are possessive or contractions; the plural-looking acronyms (the BBC's screen, MAME's own data) were checked and are possessive.

  • Hang-On has a throttle and a brake. The cabinet was a motorbike: handlebars, a twist-grip throttle and a brake lever, all analogue (MAME's AD Stick X, Y and Z), and no buttons. Its gamedoc had said it had no buttons and a stick that moved; it now lists steering on the left stick, the throttle on RT and the brake on LT, or the arrows, up and K on the keyboard. The brake needed a config file. This MAME assigns AD Stick Z to nothing, and no core option changes that, so the page writes a 20-byte MAME default.cfg at boot with one record, "AD Stick Z = right stick down", and LT stands in for that. EmulatorJS's own externalFiles could not place it, since it mounts the persistent save storage over /data/saves after writing them, so genx-ejs-boot.js gains a hook that writes a page's files on EmulatorJS's saveDatabaseLoaded event, straight after that mount and before the game starts. Play-testing found the bike slowing with RT held flat: the left stick's down still shared the throttle's axis, so a hand steering the stick eased off without meaning to. On Hang-On the left stick now steers and nothing else. Also tested: Paperboy centres, steers proportionally and the right way, and throws on A, as its page says; the core's labels put Throw on button 2.

  • A coin you can hear. A coin dropping through the slot mechanism plays when a coin goes in, from the coin door's slot or the 5 key. It is a licensed library sound (Hollywood Edge's Foley Sound Library, via SoundDogs.com), so it exists only on the web host: uploaded to the live and staging sites by hand, kept out of the repository and the release zip, protected in deploy.sh from the cleanup that would otherwise delete it, and credited in ATTRIBUTION. Without the file, the coin still goes in silently. Wiring the sound to the 5 key showed that the key could insert nothing at all. EmulatorJS reads keys only when they land inside its own game element, and focus is often elsewhere, including straight after the coin button itself, which gives up focus on purpose. A 5 pressed outside the game is now inserted by the coin door, through the same path as the slot; one pressed inside is left to EmulatorJS, so a coin is never counted twice.

  • I, Robot's camera is on the pad. The cabinet fired from the stick. Its two panel buttons were marked VIEW, and the game reads them through the start inputs: in play, 1P lowers the camera and 2P raises it. The game leans on them, too, since its Point of View killers cannot be shot and destroy a robot whose player has not moved the camera in time. Coin and start stay keyboard-only everywhere else, but on I, Robot X lowers the view and Y raises it. Y has to be pressed from code, because EmulatorJS reads player 2's start from a second pad. The gamedoc had said the panel's second button did nothing and listed Fire alone; it now lists the camera, with two strategy tips that depend on it. Also tested: I, Robot's stick centres on the core's defaults, so the Star Wars centring fix stays scoped to Star Wars, and button 2 is dead, as the core's data says.

  • The arcade gamedocs can be rebuilt from a clone. The builder had depended on control data that lived only outside the repository. tools/build-arcade-controls.py now reads it from the core's own controls.c and metadata XML at a pinned upstream commit into tools/arcade-controls.json, and tools/build-arcade-gamedoc.py runs on its own: it rebuilds every page around the copy the page already carries, or, by default, just reports any page that has drifted. The seventeen pages whose controls were set by hand keep those blocks, listed with the reason for each in tools/arcade-gamedoc-overrides.json. The first check found the stick type wrong on two pages, because the data they were built from predated the core's drivers: Ghosts'n Goblins is a 4-way stick and Kung-Fu Master an 8-way, the other way round from what the pages said. A label that already carried an entity was also being escaped twice, which no page had shipped only because those labels had all been set by hand.

  • The docs caught up with the arcade section and the handhelds. ATTRIBUTION now credits the MAME 2003-Plus core and its licence, the classic MAME non-commercial terms of 0.78, which had shipped since the arcade section landed with no entry. README's engine table gains the Game Boy, Lynx, Game Gear / Master System and arcade rows it had been missing since the handhelds arrived, and its licence summary the gambatte, handy, Genesis Plus GX and MAME cores. The wiki has a MAME 2003-Plus page, and its EmulatorJS paragraph counts five VICE bundles rather than six. README and the wiki's file map list ROMS.txt and the three arcade tools, and the wiki's home page no longer calls the release zip the whole site. docs/arcade-menu.md, a planning note that nothing linked to, is gone.

  • ROMS.txt reads as one list. Every game is Title (Year), the year taken from the system's own menu, where some sections had carried a publisher and some had carried nothing; titles sit in one column; the BBC discs use their menu names rather than ones built from filenames (Bonecruncher, Palace of Magic, and plain Elite for the Master disc); and TRSDOS and LDOS are labelled system disks rather than firmware. README and ATTRIBUTION now describe what the repo leaves out as what didn't come with its emulator.

  • The docs describe the tree as it is now. The social card's stats line reads 428 games · 34 systems · 100% self-hosted; it had been left at 328 · 33 since the arcade section landed, and was the one count the checker can flag but not fix, since it cannot read a PNG. Redrawn in the card's own font rather than a substitute — the digits were lifted from the menu row that already carried a 4, so the glyphs are the card's own. The changelog entry describing that card was wrong too, quoting 327 for a line that has always said 328. The wiki's file listing gained genx-doc.css and now describes what each stylesheet is for, and its emulator page no longer sends readers to systems/_shared/styles/genx-controls.css, which was deleted when the document language was consolidated.

  • Three panels that were laid out in space now use the pad's diamond, and Tutankham uses the right stick. X, Y and B sit in a diamond — X left, B right, Y above between them — and some of these cabinets numbered their buttons only because a panel has to: Gun.Smoke fires down the left, the centre or the right of the street; Missile Command fires from the left, centre or right missile base; Punch-Out!! throws a left blow and a right blow with the uppercut above them. Those three now sit where they point. Tutankham fires left or right along one corridor and nothing else, so it takes the right stick instead — pushed the way you want the shot to go. Which button is which was measured, not read off the numbering, and the numbering is wrong. MAME's button order is not panel order: on both Gun.Smoke and Missile Command, buttons 1 and 2 are the two outer positions and button 3 is the middle one. Missile Command prints LOW under a base that is nearly spent, so firing one button repeatedly names the base it belongs to; Gun.Smoke's shots visibly leave the sheriff to one side. This corrects a real error in two gamedocs, which had taken the numbering at face value and so had Gun.Smoke's centre and right shots the wrong way round, and named Missile Command's three bases in an order nothing had checked. Missile Command's rows now describe the bases by position, which is what was actually verified and what a player picks a base by anyway. Each of these cabinets has three buttons, so MAME 4 and 5 are cleared on them. They are unused by the board but still carried the bundle's default Y and B, and leaving them there would have put those two pad buttons on two inputs at once. Track & Field was looked at and left alone: its panel is run-action-run, which suits the diamond, but its two Run inputs are interchangeable and which one carries the action was not confirmed, so it keeps what it had. This needed per-game controls, which the shared EmulatorJS boot glue could not do: it had a perGame hook for core options only. That hook now also receives a private copy of the control map and the game's key. The copy is one level deeper than the options copy, because what a hook rebinds is an individual input's binding object — a shallow copy would have it writing into the page's own literal, and the change would then follow every game loaded afterwards in the same tab.

  • The coin door sits in a box beside the Gameplay controls link. It was floating loose on the carpet under that link, in the site's usual soft-key spot, which on this bundle is the one place a soft key does not belong: the cabinet is sized to the full viewport height, so those three buttons had wallpaper behind them and nothing to sit on. They now share the corner with the controls link as a matching box — same brown ground, same amber rule, same radius, same top edge. Its height is measured off that link rather than written down, because the label is two lines of a webfont and its height changes when the font arrives. The slot moved to the middle of the three, where the coin door is on the cabinet: 1P to its left, 2P to its right, so the button you want is on the side you are standing. Also drops a stale offset: the buttons were pushed down to clear the audio banner, which has since moved to the bottom of the screen, so the offset was pushing them towards it.

  • The five twin-stick cabinets use both sticks. Robotron: 2084 and Splat! move with one hand and fire with the other; Battlezone and Sheriff drive a tank tread with each; Inferno moves and aims. The core reads those as a separate second joystick fed from the pad's right analogue stick, so a D-pad alone could never reach them — on Battlezone the tank drove but could not steer. The right stick is now bound (and I/J/K/L on the keyboard), and the arrow keys drive the left stick as well as the D-pad, so movement is the arrow keys on all hundred machines. Verified on both: holding one tread on Battlezone pivots the tank, and the right stick on Robotron kills robots.

  • Manufacturer rows carry a date range. A maker that spans several machines — Acorn 1981-1986, Commodore 1977-1984, Atari 1977-1986 on the console side — was showing a single year, which was really just its earliest machine. Eight rows across the HOME COMPUTERS and CONSOLE menus now show the span; a maker with one machine keeps its one year. The year field widened to hold a range and is right-aligned, so all 479 dated rows on the site still close their bracket in the same column.

  • Gamedocs for the arcade section, all one hundred. systems/arcade/controls.html covers the shared panel — six buttons, the coin door, the two-stick machines, and the cabinets whose control was a trackball or a spinner — and indexes all 100 games by maker. All 100 gamedocs are written: controls on every one, a strategy section on every one, and scoring on 58. The 42 without scoring say so and why, rather than carrying invented numbers — Irem's ten have no guides with point values at all, and the early Nintendo cabinets (Radar Scope, Sky Skipper, HeliFire, Space Firebird, Space Fever, Sheriff) are too obscure to be documented anywhere on the site. GameFAQs has no arcade entry whatsoever for Gauntlet, Green Beret, Gun.Smoke or Strider. The controls in them are not recalled: the core ships its own per-game control labels, and they name the controls for 78 of the 100. That is why Asteroids reads Rotate Left / Rotate Right rather than a stick (its metadata claims an 8-way; the game has no up or down), Missile Command's three buttons read as its three missile bases, and Tempest's second button is the Superzapper. tools/arcade-labels.py corrects that data where it shouts in capitals, spells hyperspace three ways, or names a control the machine does not have — as an explicit list, so a wrong correction is visible in one place. Scoring comes from GameFAQs, which refuses anything but a real browser session; tools/gamefaqs-lookup.js runs inside one. The guides are twenty years of different authors and have no common shape — ASCII tables in <pre>, real HTML tables that run their cells together when flattened, and prose with no scoring at all — so it tries a heading, falls back to any cluster of "N points" lines, and reports failure rather than guessing. Those guides carry explicit no-reproduction notices, so only the values are taken; every sentence on the pages is written here. Where GameFAQs had nothing, the manufacturers did. Operator's manuals carry the factory settings — lives per credit, the score a spare is awarded at — which is scoring information even when the manual never prints a point table, and arcarc.xmission.com holds 1,416 of them. They are image-only scans, so they are rendered and OCR'd; the DIP tables usually sit ten to twenty pages in, past the installation instructions. That produced eleven games' worth: Space Firebird's full point table from Nintendo, Green Beret's four-row bonus-life table from Konami, Arkanoid's and Red Alert's factory switch positions, Strider's extend table, Defender's setup booklet, and the lives-and-bonus settings for Rolling Thunder, Narc, HeliFire and Kid Niki. Chase H.Q.'s manual gave the rules instead — catching the suspect extends the timer by exactly 60 seconds, and there are three turbo bursts a round. The best source turned out to be the one furthest from the arcade: the manual for the home conversion. An arcade service manual is written for the operator — wiring, switches, parts — while the cartridge manual is written for the player and prints the point table. That is where Gauntlet's scoring came from, a game with no arcade GameFAQs entry at all, along with R-Type's thirteen-enemy bestiary, Space Harrier's ground-and-sky values and Kung-Fu Master's extra life. Each is labelled as the port's figures, because a port's manual is authoritative for the port and not necessarily for the coin-op — Arkanoid proves it, awarding a spare Vaus at 30,000/60,000/90,000 at home against the cabinet's own 20,000/60,000, so that page keeps the two apart. Flyers turned out to be the weaker source for scoring but the better one for mechanics: Irem's own sheets rewrote R-Type and Image Fight, and Moon Patrol's Japanese flyer had the checkpoint table nothing else did. Nothing from a cheats, codes or secrets section was used: Space Invaders' saucer trick and Ghosts'n Goblins' tombstone exploit were both found and both left out, and the extractor skips those sections outright.

Fixed

  • help ran off the top of the screen. The prompt is a fixed 80x25 grid that rolls up like VGA — the buffer keeps growing but only the last 25 rows are ever visible, and there is no scrollback to reach the rest — and the reference was 31 rows one command per line, so a third of it had gone before the reader saw it. It is two columns now, the whole thing on one screen with the prompt still under it: NAVIGATION beside DISPLAY, FILES beside KEYBOARD, under a title that carries the two rules of the prompt on one line and a full-width rule in the menus' own Ä. It clears the screen first, so it reads as a page of its own and always lands in the same place, and leaves a blank line before the prompt returns. The columns are padded in code rather than typed as spaces, so a longer description cannot quietly knock them out of line.

  • Short wiki tables sat in a full-width box with an empty strip beside every row. The Commands page's Navigation and Keyboard tables were the clearest case: eight short rows, then half the column's width of nothing. A wiki table is display:block so a wide one can scroll inside its own box rather than squeezing the page — but a block box takes the full width the shared stylesheet gives a table, while the rows inside shrink to their content, so the border ran on long after the cells stopped. The box is sized to its content now and capped at the column, which leaves the wide ones exactly as they were, still scrolling when their content will not fit.

  • Three Intellivision menu numbers started the wrong game. Rows 8, 9 and 10 named Lock 'N' Chase, Night Stalker and BurgerTime, but the numbers behind them launched BurgerTime, Lock 'N' Chase and Night Stalker; typing a launcher's name always worked. Each row now starts the game it names. Cloudy Mountain's year moves from 1981 to 1982, its cartridge date, which re-sorts the menu. The NES menu's row 7 had named Link's Awakening, the Game Boy game, over the NES Legend of Zelda it launches, and the Atari 800XL Pole Position title said 1984 for a 1983 cartridge. Every framed menu was then checked row by row against the game its number launches, and nothing else disagrees.

  • Star Wars' yoke would not return to centre. It is one of eight cabinets whose control the core's own data calls a stick rather than one of the joyNway kinds, and the first of them tested, so the pad's left stick flies it proportionally, how far you push being how far the crosshair goes. Released, though, the crosshair sprang back to a point about a quarter of the way across the screen rather than to the middle. The axis was never the problem: held hard over, the two extremes sit symmetrically either side of centre, so only the rest position was wrong. That is set by the core's "Digital Joystick Centering", which exists for driving an analogue port from a digital stick and, with a real analogue stick on the port, pulls the rest position off centre instead. Off, the crosshair rests dead centre on both axes and the yoke behaves as the sprung one did. The mouse comes off the same game while we are there. The core drives an XY device from the mouse by default, and a mouse is relative — it has no centre to return to — which is not something a sprung yoke wants sharing its input. Both are scoped to Star Wars alone. The controls page had listed it with the trackball and spinner cabinets as "digital rather than proportional", which was true of the D-pad and the keyboard but not of the stick; it and the gamedoc now say so.

  • The Intellivision menu never got the column treatment. It is the one menu on the site whose echo is padded 16 spaces rather than 17, so the sweep that dropped the code column sitewide matched not one of its rows: it kept a four-column layout nothing else had, and sat a character to the left of every other box. Re-columned and re-indented; all 1,134 frame lines now share an indent, pair their corners correctly and run a uniform rule.

  • find could not see Capcom's 1942. It skipped launchers whose name is all digits, to avoid the numbered menu aliases — but those carry data and the loop already requires a link, so the test only ever hid the one game whose name really is a number.

[1.8.1] - 2026-09-11

Changed

  • The repository no longer carries games, BIOS or firmware that didn't come with an emulator. genx-dos.fun is unchanged and still has every one. The repo, its whole history and the release zip now hold the emulators, plus anything an emulator's own maintainer shipped with it. 382 files leave the tree and 544 file versions leave history, 644 MB in all. "Shipped by the maintainer" was settled by content, not by folder. Every candidate was hashed against the emulators' own repositories and hosted builds, and only a byte-identical match counts. That keeps jsbeeb's Acorn ROMs and the 31 BBC discs its Stairway to Hell browser serves, the whole Vectrex library jsvecx ships, the TI-99 carts in Js99'er, the Apple I tapes, VirtualT's Model 100 ROM, the nine XRoar ROMs that XRoar Online serves, and jtyone's ZX81 ROM plus the 12 tapes in its own library, once decoded from hex. Our padded Master discs, our patched 3D Monster Maze and every BIOS that didn't come with its emulator (Atari, ColecoVision, Intellivision, Lynx, Odyssey², TRS-80) go, and so, from history, do the Amiga Kickstart and the retired Mac Plus's ROM and disks. The files stay in the working tree, untracked and listed in .gitignore, so deploy.sh ships exactly what it did. build-portable.sh --no-roms builds the release zip without them, and it adds ROMS.txt, which gives every missing file's exact path and title and says we won't discuss sourcing. sdltrs.wasm had a Tandy Level II ROM embedded from its Model I build. The Model III never reads it, so its 12 KB are zeroed in place; the engine is otherwise byte-for-byte the same, and it stays in the repo.

  • The removal route is on every page a rights holder would actually land on. The site has always promised that anything bundled will be removed upon request, but that promise was linked from one place — the landing page's footer. Someone who holds rights in a game arrives at that game: its play page, its gamedoc, its machine's controls page. None of those offered any route to us, which left the one person we most want to hear from with the least obvious way to reach us. The link now sits in the credit bar on every play page, in the footer of every controls page, and in a new footer on all 428 gamedocs, which previously had none. The arcade gamedoc generator emits it too, so a regenerate cannot drop it.

  • One design language for everything you read, in one file. styles/genx-doc.css now sets the type on the controls pages, the hundred-odd gamedocs and all forty-three wiki pages: the landing page's Michroma amber headings with the rule running off the end of a section label, its serif body on the dark CRT ground, its green mono table headers. There had been two of these, and they had drifted apart without anyone choosing it — the controls sheet and the wiki sheet were parallel implementations of the same idea, at section headings of .85rem against 1rem, table headers green against amber, table type at .92rem against .88rem, and two different paragraph rhythms. The link rule alone existed in four copies, at two different border weights and two different focus rings, one of them with no focus ring at all; three of those then re-coloured links per context, so a gamedoc's cross-link was amber while the link in the sentence below it was cyan. Lists, block quotes, horizontal rules and inline code had been styled for the wiki only, so a gamedoc's bullets were whatever the browser felt like. The docs are also in the landing page's face now. They had been set in IBM Plex Serif — a second voice nothing else on the site spoke, and the reason the two halves of the site never quite looked related. Everything a reader meets is IBM Plex Mono at the landing page's 16px/1.65, with Michroma still carrying the headings. The one remaining serif, on the closing aside of every controls page, went with it. A document now loads one stylesheet. systems/_shared/styles/genx-controls.css is gone, its page frame folded into genx-doc.css, and all 463 gamedocs and controls pages link the shared sheet directly. The wiki keeps a second file for its sidebar, top bar, search box and hit list, which no other page has any use for. The one rule that could not simply move is the key/action column behaviour — a controls table shrinks its first columns to fit and gives the rest to the last one, which would have wrecked a wiki table, where every column is prose; it is scoped to the page frame those tables actually sit in. The feature article came onto the same sheet last. It had been the one document still setting its own type — serif, its own size, its own justification — and it keeps everything that makes it a feature: the measure, the kicker, the drop cap, the pull quotes and the boxout rail. Only the type is shared now. That leaves no document on the site setting its own face, and body copy is justified with hyphenation throughout, which is what the article had been doing alone. Body copy and subheadings are set the way the landing page sets its cards — subheadings in mono amber at reading size rather than shrunk into another uppercase label, and prose a shade back from --paper so that bold, links and table data carry the emphasis instead of every sentence competing for it. That colour is now a token, --prose, rather than a hex literal repeated per sheet. The controls version is the one kept, because it is the one that follows the landing page — its section heading is the landing page's .sec-label, rule and all. The wiki keeps its frame, sidebar, search box and its scrolling tables, because a wiki table is prose and can be wide; a controls table is a key/action grid and keeps its own column behaviour. Page furniture that happens to be an anchor — the masthead, the sidebar buttons, the BOOT button — is styled by its own class and is untouched.

  • The menus lost their code column. Every framed menu on the site ran four columns — number, title, year, and the DOS command that launches it — and the fourth was eating the space the titles needed. Dropping it freed eleven characters, so sixteen titles that had been squeezed to fit are now written out in full, and the year sits one space off the border instead of two. 359 dated rows and 29 yearless ones changed across 708 framed rows, every one still exactly 45 characters wide. The codes were never decorative — berzerk is a real command, and typing it still works. What's gone is the column that advertised them, which is the sort of thing a DOS user found out by typing dir anyway.

  • The game launchers are .exe files now. A launcher opens a program, so calling it berzerk.bat was describing it as a batch script, which it never was. The 351 named launchers — the ones carrying a link: — are now .EXE; the 408 numbered shortcuts and the menu.bat scripts genuinely are batch files and keep the extension. Nothing about running them changed: BERZERK, berzerk.exe and the menu number all still work, because the shell matches on the base name and checks for a link before it ever looks at the extension. TYPE BERZERK.EXE now does what DOS did — prints the program's bytes as CP437 glyphs, starting MZ, and stops dead at the first Ctrl-Z, which is why you get a short burst of noise rather than a screenful. The bytes are generated from the filename rather than stored, so each program has its own stable garbage and fs.js doesn't gain 351 blobs of it. Five byte values are shifted into printable range because the console acts on them instead of drawing them — bell, backspace, tab, linefeed, carriage return — exactly the five DOS's own console consumed. Deliberately absent: This program cannot be run in DOS mode. That string belongs to the Windows PE stub, and a machine pretending to be a DOS box has no business printing it.

Fixed

  • Twelve vendored images that nothing used were shipping to every BBC visitor. jsbeeb's own web UI has an example screenshot, a sidebar, a bottom bar, two disc-drive icons and an app icon; our embedded build uses none of them — its page asks only for the cub monitor and a placeholder — but all six were in the tree twice, once per BBC machine, and all twelve reached the web host. Removed. They will come back if the fork is ever re-vendored, so the re-vendor recipe should strip them.

  • We were sending Chrome, Edge, Brave and Opera players to another browser over a fault on one machine. An orange banner on the CoCo and Vectrex pages told every Chromium visitor that "USB controllers are not recognised" and to use Firefox instead; six Vectrex gamedocs, two CoCo gamedocs, the Vectrex controls page, the README and two wiki pages all said the same. None of it was true. The cause was local: the browser those findings were made in is a Flatpak, and the sandbox had no /run/udev. A browser enumerates gamepads through udev on Linux, so it found none — on every site, in every emulator, focused or not. The device node itself was readable the whole time, which is why it looked like an emulator problem: the pad was plainly there, and nothing could see it. Two engines were blamed for it in turn, one of them twice. With udev visible, the same pad drives Vectrex Berzerk and CoCo Galactic Attack in Chrome, on the same pages, over plain HTTP — full analogue range on the Vectrex's stick, which is the control that machine is actually about. The banner and its script are gone, and the pages now say the one thing that is true of every browser: a pad is only handed over once a button is pressed on a focused page, so click the game area and press again.

  • Every EmulatorJS bundle was booting its core with an empty options file. The arcade cabinet opened on MAME's copyright warning however skip_disclaimer was set, and the reason turned out to be sitewide: EmulatorJS writes the core's option file from getCoreSettings(), and that function consults the page's defaults only when the browser has no localStorage or when this game already has a saved settings entry. The entry is keyed per ROM URL and is only written once a player changes something, so on a first visit — every visitor's first visit to every one of the site's EmulatorJS games — the file was written empty and the core ran on its own factory settings. The C64's true drive emulation, the arcade's two skip options, the joyport type: none of them were reaching a core until the player had been into the settings menu and changed something at random. The page's defaults are now appended to whatever EmulatorJS writes, in its own format, for any option it did not write itself. A saved setting still wins, which is the point of a saved setting. Done in our own boot glue rather than by editing the vendored runtime, hooked through a property setter so it lands the moment the emulator is constructed — well before the core asks for the file.

  • find has never once printed a game's title. It parses each menu's rows to learn what a launcher is called, and its pattern expected the echo and the box border to be adjacent — but the menus are padded out to centre the box, so the pattern matched no row anywhere on the site. Every result fell back to the launcher name printed twice: DEMON DEMON. The wiki's example output showed titles because it had been written from intent rather than from a run; it is now generated from the real thing. Fixing the pattern exposed the second half: with the code column gone there was nothing left to key titles on, so the index is rebuilt on the row number instead, which the numbered .bat beside each row resolves to a launcher (smb) or a sub-directory (cd bbc). That last part is new — directory rows never resolved before, so find acorn said ACORN ACORN and now says Acorn (1981).

  • Pokémon Red had a Greek capital theta in it. The font sheet is indexed by character code — charCodeAt picks the sprite directly, with no Unicode translation — so a glyph is written as whatever character sits at that code, which is why the box borders are spelled ÉÍ»º. The title had been written with a real é (U+00E9 = 233), and sprite 233 is CP437's Θ. It now holds char 130, CP437's actual é, written as \x82 rather than the invisible control character that lives at U+0082. Swept the other 397 menu titles for the same mistake: Odyssey² is the only other non-ASCII one and it was already right. Nothing else on the site renders a character it doesn't mean to. Searching for it was fixed properly rather than patched. find had a special case truncating any query starting with odyssey, because Odysseyý could never match what a person types; that is replaced by a fold applied to the title before matching — CP437's accented-letter block back to plain letters, 253 to 2 — plus a retry with spaces stripped from both sides. So find pokemon and find "odyssey 2" both land, and the next title that needs a trick glyph needs no code at all.

  • dir and find crashed on the three handhelds. The Game Boy, Lynx and Game Gear directories were written without the empty files and directories arrays every other directory has, and both commands index those arrays without checking. cd gameboy followed by dir threw, and find threw on any query, because it walks the whole tree and always reached them. Nothing about the games was wrong — six missing []s.
