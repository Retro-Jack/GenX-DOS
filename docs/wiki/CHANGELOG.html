Added

  • The wiki has search. Forty-three pages had no way to find anything in them but the sidebar and guesswork. build.py now indexes every page by section — 504 of them — and generates a Search.html that filters as you type, ranks a heading match above a body match, and links each hit straight to the section anchor it came from. The interesting part is the content policy. These pages run default-src 'none' with no script-src, which is why not one of them has ever executed a line of JavaScript, and that is a property worth keeping. So the search page carries the standard policy plus the SHA-256 of exactly the script it contains — not 'unsafe-inline', which would permit any inline script on the page. The hash is computed as the script is written, in the same function, so the two cannot drift apart. Every other page in the wiki is untouched and still runs nothing. The index is inlined rather than fetched, so the page needs no connect-src and works from a downloaded copy with no server at all — fetch() of a local JSON would be blocked as cross-origin from file://. Section text is capped at 700 characters, which took the page from 224 KB gzipped to 107 KB while leaving every section findable by its heading and its opening.
